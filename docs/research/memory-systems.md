# Sass And Memory Systems

## Observed behavior

The dated local Sass review recorded semantic recall, deduplication, age
pruning, hard caps, scheduled distillation, compact profiles, and
recent-response tracking. Plume's current memory documents translate those
behavioral lessons into coding facts, task outcomes, verifier evidence, and
repeated-patch avoidance without importing Discord-specific personality or
behavior.

## Plume adaptation

Keep memory inspectable, bounded, redacted, project-scoped, and unable to grant
permissions. Grow retrieval in visible stages: lexical selection, preview,
explicit insertion, measured semantic retrieval, then only evidence-backed
opt-in automation.

## Already shipped overlap

Plume ships memory CRUD/search, bounded prompt inclusion, curated topics,
manual exact-duplicate distillation, and user-managed links from memories to
topic files. Those links are organization metadata only: they do not select,
retrieve, or inject prompt context.

## Remaining gap

The Knowledge workspace, explicit context shelf, semantic evaluation set,
semantic retrieval, contradiction handling, generated profiles, and richer
auditable distillation remain open.

## Rejected or deferred

Invisible memory writes, permission-granting memory, automatic context from
topic links, and Discord-specific behavior are rejected. Dreaming and
background consolidation are later opt-in work requiring resource budgets,
visible traces, review, and undo.
