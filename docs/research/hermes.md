# Hermes Agent

## Observed behavior

The public Hermes repository and documentation describe a persistent agent
runtime with typed presentation events, progressive tool disclosure, session
history and search, memory-provider lifecycle hooks, skills, scheduling,
background processes, and multiple provider/platform adapters. The deeper
clean-room evidence record remains in
[HERMES_AGENT_RESEARCH.md](../HERMES_AGENT_RESEARCH.md).

## Plume adaptation

Adapt the runtime spine selectively: typed events, bounded prompt tiers,
procedural skills, auditable memory lifecycle, progressive disclosure, and
resource-aware background states. Keep Plume's distinct center: MLX-first local
model ownership, a native coding editor, visible approvals, and safe
diff/apply/revert.

## Already shipped overlap

Plume ships persisted searchable sessions, bounded redacted project memory,
curated topics, explicit distillation, project skills, local runtime
diagnostics, and a single safe patch-producing agent step. The broader agent
loop and execution toolchain are not shipped.

## Remaining gap

Plume still needs a bounded real executor, richer typed agent events,
progressive execution-tool disclosure, scheduled/background work, and isolated
subagent lifecycle support before it approaches Hermes-class runtime breadth.

## Rejected or deferred

Do not copy Hermes source, schemas, scoring, or platform breadth. Upstream
license permission and Plume's clean-room policy are separate gates; a
permissive license does not automatically put source reuse inside this roadmap.
Browser/computer-use execution and broad gateway integrations remain deferred
behind Plume's own capability, approval, and safety gates.
